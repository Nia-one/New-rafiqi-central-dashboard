# Self-Drive Loop Health foundation

Status: locked shared contract for the seven Rafiqi Central self-drive loops, 17 July 2026.

Every domain implements **Detect → Contextualise → Decide → Act → Verify → Recover → Learn**. RafiQi Inside is the verified read-only exhaust; Operations Control owns work, clocks, evidence and closure.

## Required report face

Each domain renders one question, one plain answer, exactly four measures, one primary visual, one compact Operations Control strip and one shared Loop Health strip. The first viewport reads Target → Current → Gap → Owner → Progress → Verified result. Use one H1 and the existing calm blue, grey, black and white design system.

## Loop Health contract

The shared strip always exposes:

1. Data freshness against the feed's registered cadence. Stale dependent claims remain visible, turn grey and show their age.
2. Running and breached clocks. Standard users see the responsible role, not a person's identity.
3. Claimed, independently verified, awaiting-verification and reopened outcomes.

A domain cannot publish a healthy Overview answer when any critical feed is beyond twice cadence, any clock is breached or the oldest verification backlog is beyond 48 hours. It must publish `Cannot confirm — reason`.

## Non-negotiable integrity rules

- Stable event and message idempotency keys.
- Repeated detections update existing work rather than duplicating it.
- Executor and material verifier differ.
- Closure requires source-metric recovery, not a completed checkbox.
- Audit history is append-only.
- Safety and urgent Member protection outrank routine commercial work.
- Missing live data blocks live action, not typed synthetic/shadow development.
- No live message, payment, pricing/terms change, contract, capital commitment, route assignment, GPS tracking, Production write or Studio release is enabled by this foundation.
